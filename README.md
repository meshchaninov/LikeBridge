# LikeBridge

Лайк трека → заявка на альбом или отдельную запись в DroppedNeedle. Небольшой self-hosted сервис с русским UI, очередью и ручным выбором спорных совпадений.

## Возможности

Тёмная тема используется по умолчанию на всех экранах, включая вход и окна подключения.

- **Яндекс Музыка:** чтение «Мне нравится» через токен неофициального API.
- **Spotify:** OAuth Authorization Code + PKCE, `user-library-read`, обновление токенов и постраничное чтение Liked Songs.
- **Apple Music:** вход через MusicKit либо Music User Token; выбор плейлиста «Любимые песни» в UI. Нужен Apple developer token. Поддерживаются любые выбранные библиотечные плейлисты.
- В каждой карточке: **«Только трек»** или **«Весь альбом»**. В настройках выбирается режим для новых лайков и массовой обработки старых; ранее поставленные заявки сохраняют свой режим. Подписка на дискографию не включается.
- Очередь отсортирована по настоящей дате лайка: новые сверху, даты Яндекса и Spotify объединяются. В карточке видны дата и время. Если источник не возвращает дату лайка (например, текущая интеграция Apple Music), такие треки находятся в конце, с пометкой «Дата лайка недоступна». Дата импорта не подставляется вместо даты лайка.
- Дедупликация альбомов по MusicBrainz release-group ID, треков — по recording ID, между источниками и после перезапуска. Два разных трека одного альбома обрабатываются независимо; старая история альбомных заявок сохраняется.
- Автоматическая отправка только при почти точном совпадении исполнителя, альбома и года и достаточном отрыве от других вариантов. Остальное — в ручную очередь.
- Сингл остаётся синглом. Сборники, deluxe, remaster и переиздания не заменяются «обычным» альбомом автоматически.
- У каждого трека: кнопка 30-секундного фрагмента, поиск на YouTube и ссылка на исходный сервис. Фрагмент находится через существующий DroppedNeedle только по нажатию; звук идёт напрямую с CDN в браузер. Один общий плеер, без скачивания и хранения аудио на сервере. Наличие превью зависит от каталога, региона и доступности внешних сервисов.
- Обложки в очереди и вариантах совпадений: метаданные Spotify/Яндекса/Apple Music и Cover Art Archive, отложенная загрузка в браузере, заглушка при отсутствии. Сервер не хранит изображения в RAM или на диске.
- Первый запуск по умолчанию сохраняет старые лайки как baseline; новые обрабатываются автоматически. Старые можно отправить по одному или все порциями.
- Снятие лайка не удаляет файлы. Источники никогда не изменяются.
- Один Python-процесс, один поток синхронизации, SQLite WAL. Очередь хранится на диске; UI без фреймворков и Node.js в рантайме.

**LikeBridge передаёт заявки, не скачивает аудио из стриминга.** DroppedNeedle скачивает через свои настроенные источники. Статус «Заявка отправлена» означает принятие API, а не завершение скачивания: дальнейший прогресс смотри в DroppedNeedle.

## Запуск

```sh
cp .env.example .env
# Заменить SETUP_TOKEN случайной строкой, задать PUBLIC_URL.
docker compose up -d --build
```

Открой `http://127.0.0.1:8789`. При первом входе укажи SETUP_TOKEN и придумай пароль из 12+ символов. Альтернатива для автоматического развёртывания: передать `ADMIN_PASSWORD` при первом запуске; в базе будет сохранён хеш. После установки пароль меняется через UI, изменение переменной его не сбрасывает.

Если нужен доступ с другого устройства, используй HTTPS reverse proxy и `COOKIE_SECURE=1`, `PUBLIC_URL=https://your-host`. `compose.yaml` публикует порт только на loopback. Для домашнего сервера есть `compose.home.yaml` с существующими сетями `traefik` и `arr_music` и LAN-only middleware:

```sh
docker compose -f compose.yaml -f compose.home.yaml up -d --no-build
```

### Подключение DroppedNeedle

В «Подключения» задай URL, API version и логин/пароль пользователя роли Trusted или Admin. Пароль нужен для автоматического перевхода, когда сессия истечёт. Можно использовать только Bearer token, но обновлять его придётся вручную. При сохранении выполняется проверка `/auth/me`.

Для DroppedNeedle **v2.15.0** используется `/api/v1`: проверено на домашнем экземпляре. Для v3 есть переключатель `/api/v3`, но совместимость форм запросов и ответов с v3 не подтверждена; перед использованием проверь её на своей версии. Параметр Origin нужен, если приложение ожидает публичный URL за reverse proxy.

### Одиночные треки

Нажми «Только трек» в карточке: сервис найдёт recording ID и вызовет `/tracks/{recording_mbid}/request`, без альбомной заявки. Сначала проверяется состав найденного альбома в DroppedNeedle. Если совпадения нет, выполняется ограниченный поиск записей в публичном MusicBrainz API (User-Agent, не чаще одного запроса за 1.1 с); неточные варианты ждут ручного выбора. В ручном поиске трека можно вводить MusicBrainz/Lucene запрос.

Проверка уже скачанного одиночного трека выполняется самим DroppedNeedle. Наличие какого-либо файла альбома не считается наличием каждого его трека. Усечённые названия версий не подменяют ремикс оригиналом автоматически. Для сборников хранится отдельно исполнитель трека и исполнитель альбома.

После запроса отдельного трека можно выбрать «Весь альбом», чтобы получить остальное. История треков и альбомов раздельная. Если отправка не подтверждена, её повтор по-прежнему требует проверки и явного разрешения.

Способ получения файла зависит от клиента DroppedNeedle. В частности, через Usenet он может скачать альбомный NZB и извлечь нужный трек; LikeBridge передаёт именно одиночную заявку, но не гарантирует, что источник передаст только один файл по сети.

### Музыкальные аккаунты

**Яндекс:** нажми «Подключить» и вставь токен Яндекс Музыки. Ссылка на инструкцию получения есть в UI. Токен проверяется до сохранения. Это не OAuth-клиент, зарегистрированный в Яндексе; используется [неофициальная библиотека](https://github.com/MarshalX/yandex-music-api), и изменения API могут потребовать доработки.

**Spotify:** создай приложение в [Developer Dashboard](https://developer.spotify.com/dashboard), добавь точный Redirect URI из UI и свой аккаунт в allowlist. В development mode нужен Premium у владельца приложения. Введи Client ID и войди через Spotify. Client Secret не нужен. Spotify принимает HTTPS redirect; HTTP допустим только для явного loopback `127.0.0.1`, не `localhost` и не LAN IP. Локальный сертификат должен быть доверенным на устройстве.

**Apple Music:** создай developer token с MusicKit в Apple Developer Program, введи его и нажми «Войти через Apple Music». Получи плейлисты и явно выбери «Любимые песни». Автоматическое угадывание по локализованному названию не используется. Developer token и Music User Token имеют срок действия; при истечении подключи заново. Реальное подключение требует действующих пользовательских аккаунтов; автоматические тесты используют изолированные ответы API.

## Память и ограничения

Контейнер ограничен **128 MiB RAM**, swap отключён для контейнера, CPU — 0.5 ядра. Нет Redis, PostgreSQL, браузера или JS-сервера. Обложки загружаются напрямую браузером с CDN музыкальных сервисов; сервер хранит только ссылки. Аудио не кэшируется. SQLite page cache — 1 MiB на соединение, 4 HTTP-потока, один фоновый поток; журнал ограничен 200 событиями.

Лайки проверяются раз в 10 минут, за цикл обрабатывается до 10 треков; оба значения меняются в UI. Источники читаются страницами; Яндекс возвращает список всех ID лайков перед загрузкой полных данных порциями по 50, поэтому очень большие библиотеки требуют дополнительной памяти. Измерения конкретного развёртывания смотри в `VERIFICATION.md`.

Очередь и история треков растут на диске. Повторный лайк ранее обработанного трека не создаёт вторую заявку. Глобальная дедупликация идёт по MusicBrainz ID; разные группы релизов одного альбома могут потребовать ручной проверки.

При сбое между отправкой запроса и подтверждением сохраняется `uncertain`: слепая повторная отправка блокируется. Поиск может подтвердить, что заявка уже есть, и пометить её существующей. Если каталог ещё не видит заявку, проверь Requests в DroppedNeedle. «Повторить поиск» безопасно, но не снимает эту блокировку. После ручной проверки можно разрешить повторную отправку из очереди.

## Безопасность и резервное копирование

- Вход по паролю, PBKDF2-SHA256 hash (1 000 000 итераций, без большого выделения RAM на вход), CSRF, проверка Origin, HttpOnly/SameSite cookies.
- Учётные данные зашифрованы Fernet; `encryption.key` лежит рядом с базой с правами 0600. Шифрование не защищает от администратора сервера, читающего весь volume.
- Контейнер работает от UID 10001, без capabilities, с read-only root filesystem. Доступ к Docker socket отсутствует.
- `.env`, база, ключи и пользовательские данные исключены из Git и Docker build context. Не выкладывай их в GitHub.
- Для бэкапа останови **только LikeBridge**, скопируй весь volume `likebridge_likebridge-data`, затем запусти контейнер. Нужны и база, и encryption.key. Не копируй только `likebridge.db` при работающей WAL-базе.
- `PUBLIC_URL` задаёт единственный внешний Host. Не публикуй сервис в интернет без настройки HTTPS и соответствующей защиты reverse proxy.

## Разработка и тесты

Python 3.11+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock pytest==9.0.1
.venv/bin/python -m pytest -q
node --check likebridge/static/app.js
ADMIN_PASSWORD=local-development-password DATA_DIR=./data .venv/bin/python -m likebridge
```

Тесты проверяют authentication/CSRF/Origin, шифрование и сокрытие токенов, baseline, новые лайки, переподключение, консервативный матчинг, межсервисную дедупликацию, backoff, одноразовый OAuth state, обновление Spotify token, пагинацию Apple и реальный HTTP-сценарий с изолированным DroppedNeedle-двойником. Сетевые запросы к пользовательским аккаунтам в тестах отсутствуют.

Зависимости зафиксированы транзитивно в `requirements.lock`. `requirements.txt` — прямые зависимости. Для контейнера используется lock.

### Порог автоматического выбора

В настройках синхронизации можно указать порог от 0 до 100% (по умолчанию 70%). При включённой автоматике лучший результат с оценкой **не ниже** порога отправляется в DroppedNeedle; близость второго результата не блокирует выбор. Оценка отражает сходство метаданных, а не вероятность правильного выбора. Если альбом ниже порога или не найден, включённый переход к треку запускает поиск записи; при отсутствии подходящего трека остаётся ручной выбор. При сохранении настроек подходящие заявки со статусом «Нужен выбор» возвращаются в поиск; пропущенные записи и исходный список старых лайков не затрагиваются. Неопределённые отправки остаются заблокированными до ручной проверки.

В списке вариантов для ручного выбора рядом с каждым альбомом и треком есть «Пример» и ссылка на YouTube. Пример ищется по метаданным выбранного варианта только после нажатия, играет в общем плеере до 30 секунд и не создаёт заявку на скачивание. Для альбома используется первый доступный фрагмент из его начальных треков; конкретное издание может отсутствовать у поставщика фрагментов. Если пример недоступен, остаётся YouTube. Аудио воспроизводится с CDN напрямую, без серверного кэша.

### Альбом не найден: отдельный трек

По умолчанию включена настройка «Если альбом не подобран — искать и скачивать отдельный трек». Если лучший альбом не достигает заданного порога (или результатов нет), сервис ищет сам понравившийся трек и отправляет одиночную заявку при достижении того же порога. Подходящий альбом имеет приоритет. При выключенной автоматике одиночные заявки автоматически не отправляются. Ошибки каталога обрабатываются повторными попытками. Старые лайки в исходном списке и пропущенные записи не запускаются; ожидающие выбора альбомы проверяются при включении настройки и первом обновлении. Неопределённая отправка альбома блокирует такой переход до проверки. Тип заявки сохраняется перед отправкой, поэтому перезапуск и лайк того же трека из другого сервиса не создают повторную заявку.
